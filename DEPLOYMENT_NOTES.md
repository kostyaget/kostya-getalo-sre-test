# Deployment Notes

Опиши тут своє рішення. Коротко, по кілька речень на пункт.

## Chosen architecture

Що підняв і чому саме так (сервіси, контейнери / процеси, де що живе).
------------------------------------------------------------------------
Docker Compose, 5 контейнеров: app, queue, nginx, mysql, redis.

Docker Compose — всё поднимается одной командой, работает независимо от 
среды (локально и на сервере одинаково).

nginx порт 80 наружу.

MySQL и Redis доступны только из докера (не открыты наружу).

app и queue — один образ, разные команды запуска, чтобы код не 
расходился по версиям.

## Server preparation

Як готував чистий VPS (користувачі, доступ, hardening, залежності, 
firewall).
-----------------------------------------------------------------------
создал обычного пользователя kastet с sudo, вместо работы от root.

сгенерировал SSH-ключ на своей машине, добавил публичный ключ в 
authorized_keys пользователя

отключил вход по паролю и вход под root напрямую (PermitRootLogin no, 
PasswordAuthentication no в sshd_config) - теперь зайти можно только по 
ключу и только под обычным пользователем для безопасности

Столкнулся с тем, что cloud-init (авто-настройка при создании VPS) 
добавляет свой отдельный файл 50-cloud-init.conf с 
PasswordAuthentication yes, который читается раньше основного конфига и 
перебивает мои настройки - SSH использует первое найденное значение 
параметра, поэтому мой запрет пароля игнорировался. Поменял значение 
прямо в этом файле.

## What would be improved next

Чесно: що лишилось поза скоупом і що зробив би далі для реального проду.
-----------------------------------------------------------------------
Заметил, что nginx у меня подключает папку public/ напрямую с моего 
компьютера (через volume), а вот команда storage:link, которая должна 
создавать ссылку на папку с файлами, срабатывает только внутри 
контейнера app — то есть это как будто две разные папки, которые не 
видят друг друга. Прямо сейчас это не мешает, потому что в проекте нет 
загрузки файлов вообще. Но если бы она появилась — было бы круто это 
починить, чтобы оба контейнера смотрели в одно и то же место. По идее 
для этого нужно сделать общее хранилище (volume) между app и nginx, и 
чтобы app при старте сам туда копировал нужные файлы и делал symlink — 
тогда nginx бы видел актуальную версию, а не только то, что было на 
момент сборки образа
