# SRE Test — Laravel MVP Deploy

Завдання: взяти цей Laravel-проєкт і чистий VPS, підготувати сервер і задеплоїти застосунок так, як ти вважаєш правильним для production-like MVP.

Як саме це робити — на твій розсуд. Ми не навʼязуємо стек. Головне — щоб рішення було зрозуміле, повторюване, і щоб ти міг пояснити, чому зробив саме так.

## Що ти отримуєш

- цей репозиторій — Laravel application у `app/`;
- 1 чистий VPS (Ubuntu) з public IP;
- root SSH доступ до VPS — надішлемо окремо;
- домену немає;
- Cloudflare token немає.

Працюємо тільки по public IP.

## Що треба зробити

Підготувати сервер і розгорнути цей Laravel-проєкт як production-like MVP.

Очікуємо, що в результаті:

- застосунок доступний по public IP;
- сервер підготовлений безпечно на базовому рівні;
- deploy повторюваний і зрозумілий;
- secrets не лежать у Git;
- DB / Redis та інші internal-сервіси не відкриті назовні;
- логи можна подивитися;
- є план backup і restore;
- є базовий моніторинг — або чітко описано, що і як моніторити;
- ти описав, які проблеми знайшов у застосунку і як їх виправив;
- ти описав, чому вибрав саме такий підхід.

> Стартовий проєкт може містити проблему (або кілька), яку варто знайти і виправити. Це не «вгадайка» — все знаходиться через логи, конфіг і поведінку застосунку. Опиши знайдене в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Стек — на твій розсуд

Ми **не вимагаємо** конкретного стеку. Docker, Ansible, CI/CD, systemd, bare-metal, bash — обирай сам.

- Використовуєш automation (Ansible тощо) — добре, це плюс.
- Використовуєш Docker — коротко поясни, чому.
- Робиш CI/CD — опиши, як воно працює.
- Не робиш щось із цього — опиши, як би додав це наступним кроком.

## Definition of Done

- [ ] застосунок відкривається по public IP;
- [ ] сервер можна відтворити / передеплоїти за описаними кроками;
- [ ] environment variables і secrets зберігаються безпечно;
- [ ] persistence бази / storage продумано;
- [ ] логи описані — де вони і як дивитися;
- [ ] backup і restore описані;
- [ ] моніторинг / алерти реалізовані або чітко описані;
- [ ] знайдені проблеми застосунку задокументовані;
- [ ] архітектурні рішення задокументовані.
