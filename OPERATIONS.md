Коротко, як експлуатувати сервіс. Заповни розділи.

## Health check

Як перевірити, що сервіс живий — ззовні і на сервері.
----------------------------------------------------------------
Снаружи: curl http://IP/health (не полный чек, я так понял что он проверяет на жизнь php-fpm) или curl http://IP/up (лучше юзать этот стандартный от ларавель с большим потенциалом для проверки, можно подключить доп проверки к нему )
Оба возвращают успешный ответ.
На сервере: docker compose ps - все контейнеры должны быть Up, у mysql 
статус (healthy).

## Logs

Де логи застосунку і веб-сервера, якими командами дивитися, як шукати помилки.
------------------------------------------------------------------------------------------------    
логи приложения по этому пути storage/logs/laravel.log 
чек логов {docker compose exec app cat storage/logs/laravel.log}

логи веб сервера можно увидеть через докер просто запросив логи с контейнеров 
docker compose logs app
docker compose logs queue
docker compose logs nginx
docker compose logs mysql

Docker: Искать ошибки можно просто узнав какие контейнеры упали через {docker compose ps} дальше уже смотреть логи по упавшим контейнерам, если контейнеры живут но есть видимые проблемы то просто запросить логи по всем контейнерам и проверять каждый на наличие алертов, лучше заправшивать логи по всем контейнерам сразу потому что погут быть не видимые ошибки и они будет просто копится в логах 

логи веб-сервера (nginx) смотрятся через docker compose logs nginx - образ nginx по умолчанию пишет логи в stdout/stderr

## Restart services

Як перезапустити сервіси / застосунок.Ы
----------------------------------------------------------------------------------------------------
быстрая перезагрузка приложения {docker compose restart app} без пересборки образа 

после измений кода нужно испольщовать перезборку {docker compose up -d --build} пересобирает только контейнеры в которых были изменения, там где изменений не было не трогает 

полная остановка и запуск, обнуляет контейнеры (так сказать для чистого запуска)
docker compose down
docker compose up -d

## Backup

Що бекапиться (база + storage), як запустити, розклад, retention.
-------------------------------------------------------------------------------------------------------
Бэкапится база MySQL (дамп через mysqldump, сжатый gzip) и папка storage/app/public (для будущих загруженных файлов)
Скрипт scripts/backup.sh — запускается вручную командой ./scripts/backup.sh, или автоматически через cron каждый день в 3:00 ночи.
Старые бэкапы (старше 7 дней) удаляются автоматически. Логи бэкапов пишутся в ~/backups/backup.log.

## Restore

Покроковий runbook відновлення з бекапу.
---------------------------------------------------------------------------------------------------------
найти нужный файл бэкапа, файлы называются (db-ДАТА-ВРЕМЯ.sql.gz)
ls -lh ~/backups/

восстановить базу из выбранного файла
gunzip -c ~/backups/db-ДАТА-ВРЕМЯ.sql.gz | docker compose exec -T mysql sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" mvp'

проверить, что данные реально вернулись
docker compose exec mysql sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" mvp -e "SHOW TABLES;"'

проверял сам вручную, адалил таблицу sessions и восстановил из бекапа

## Useful debug commands

Корисні команди для швидкої діагностики.

docker compose ps                          # статус всех контейнеров
docker compose logs <service> --tail=50    # последние логи сервиса
docker compose logs <service> -f           # логи в реальном времени
docker compose exec app sh                 # зайти внутрь контейнера app
docker compose exec app cat storage/logs/laravel.log   # логи приложения
docker stats                               # потребление CPU/памяти по контейнерам
docker volume ls                           # список volume'ов (для проверки persistence)
